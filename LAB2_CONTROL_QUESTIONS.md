# Контрольні запитання до лабораторної роботи №2

Тема: Багатопотоковість. Асинхронність. IEnumerable. LINQ.

## 1. Процес і потік

Процес — це запущена програма зі своєю власною областю пам'яті (свої файл
системи, свої змінні середовища, своя таблиця вихідів). Потік (thread) — це
найменша одиниця виконання всередині процесу. Один процес може містити
кілька потоків, і вони спільно використовують пам'ять процесу. Особливо
важливо: потоки одного процесу бачать однакові спільні змінні, саме це
вимагає синхронізації (lock, семафор, події). Ядро ОС перемикається (switch)
між потіками; бібліотека Thread Pool .NET створює «потік-пул» — набір
потоків-працівників, на яких виконуються завдання.

## 2. Багатопотоковість

Багатопотоковість (multithreading) — виконання кількох потоків одночасно:
велике обчислення або велика задача розбивається на частини, і вони
виконуються різними потоками одночасно. Задача: збільшити швидкість або
паралелізувати IO-операції (файли, мережа, API). Вимога: спільний стан
(shared state) має бути захищений синхронізацією, інакше гоніжка потоків
(race condition) «з'їсть» дані.

## 3. async vs multithreading

- **async (асинхронність)** — потік чекає (await) «неблокувальні» API.
  Поки потік чекає підсумок (IO, API), пул може обслуговувати інше.
  Потік не «залишається без діла» — він виконує іншу роботу.
- **multithreading (багатопотоковість)** — реальні потоки, кожен
  зі своїм stack'ом викликів. Обчислення йде паралельно, але кожен
  потік використовує CPU-ядро.

Кожен використовуємо там, де він потрібний:
- async CRUD, SaveAsync — для IO (файли, API, DB).
- Parallel / Parallel.For — для CPU-bound обчислень (в нас — створення
  2000 об'єктів).

## 4. async/await

`async` — компілятор перетворює метод на автомат, який повертає
`Task` / `Task<T>` / `Task<TResult>`. `await` — оператор «зупинитися і
побачити результат Task»; потік пулу відпускається, і метод продовжується
на тому ж потоці (context). await **не блокує** потік: потік пулу виходить
з методу, виконує інше, і повертається туди, де «зупинилися». Це дає
масштабованість: одна потік пулу може обслуговувати багато (або безліч)
запитів одночасно.

## 5. Task та ValueTask

`Task` — reference-обгортка (контейнер) асинхронної або фоновості
(потенційно) дії; зберігає стан, результат (для Task<T>) і можливе
виключення. `ValueTask` — value type: легша обгортка, коли Task
потенційно уже завершений або результат не зберігається в пам'яті
(без GC-збірки). ValueTask використовуємо у «гарячих» шляхах (hot path),
де виклик часто, або там, де результат Task потужно (потенційно) виконаний
раніше. Task — у загальних випадках (зворот в memory, GC, зібрати
всередині обгортки).

## 6. Thread-safe колекції .NET

Thread-safe — безпечна для одночасного доступу з різних потоків:
кожна операція (insert, remove, read, enumerate) є атомарною, і lock
на сторони програміста не потрібен. .NET пропонує
`System.Collections.Concurrent`:

- `ConcurrentQueue<T>` — черга (FIFO), `Enqueue` / `TryDequeue`;
- `ConcurrentDictionary<TKey, TValue>` — словник,
  `AddOrUpdate` / `TryGetValue` / `TryRemove`;
- `ConcurrentBag<T>` — «кошик», `Add` / `TryTake`, без сортування;
- `ConcurrentStack<T>` — стек (LIFO), `Push` / `TryPop`.

У нашому проєкті: `ConcurrentQueue<int>` у producer/consumer (буфер),
`ConcurrentBag<Song>` у Parallel-демонстрації.

## 7. lock

`lock (gate) { ... }` — взаємне виключення: критична секція (block)
виконується **один потік**, інші чекають, поки `gate` вільний. `gate`
— instance-об'єкт (не int і не string, бо ці та рядки — не ключі блоку).
Внутрішні реалізації: `monitor.Enter(gate)` і `monitor.Exit(gate)`
у `finally`. **Не утримуйте lock через await**: await змінює потік, а
lock прив'язаний до конкретного потоку і не може бути «переданий»
в інший. Для async-коду — `SemaphoreSlim`.

## 8. Semaphore (сематор)

Semaphore (лицензій-лічильник) — об'єкт, що «дозволяє» N потікам
одночасно увійти в ресурс: Wait — забрати одну ліцензію (або не
чекати, а чекати; якщо немає, чекати), Release — повернути ліцензію.
Semaphore (клас, `System.Threading`) — реалізація-об'єкт, яка
використовується у синхронних (без await) випадках і для очікування
понад потоки (потік не пул, а різні). Semaphore — «старий»
реестр-об'єкт, і його Wait блокує потік. Для async-складин (async
stack) — SemaphoreSlim.

## 9. SemaphoreSlim

SemaphoreSlim — сучасна, швидша реалізація лічильника, яка
підтримує **async**: `await WaitAsync()` і `await Release()`.
Потік пулу не блокується, очікування асинхронне, і пул може виконувати
інше під час очікування. У нашому проєкті: **статичний SemaphoreSlim
на рівні 1** (`_jsonWriteGate`) захищає конкурентні `SaveAsync` —
одночасно пише файл лише один writer, і JSON ніколи не ламається.
Або: 10 worker'ів, maxConcurrency = 3, для демонстрації обмеження
одноразовості.

## 10. AutoResetEvent

AutoResetEvent (подія з автоматичним скиданням) — стан, який потіки
можуть «чекати» і «ділитися» «сигналом». `Set()` — «подія сталася»:
пробуджує **один** потік, який чекає `WaitOne()`, і одразу
переходить в стан очікування (reset). `Reset()` — «сигнал зник»:
наступний `WaitOne()` зупинить (закриє) потік, поки `Set()`.
`WaitOne(timeout)` — «нульовий» (неблокуючий) запит: повертає `bool`,
true якщо подія вже виставлена, false інакше, без чекання.
У нашому producer/consumer: `itemReady` (елемент в буфері) та
`producerFinished` (все вироблено) — обидва AutoResetEvent.
Deadlock (мертве блокування) неможливий, бо потіки чекають в односторонньому
направленні (producer —> consumer).

## 11. Захист shared resource (спільної ресурсу)

Shared resource (спільний ресурс) — ресурс, до якого доступ у багатьох
потоків: спільна змінна, файл, база даних, колекція. Якщо не захищено —
гоніжка (race condition): зростання (`counter++`) «з'їдається», файл
ламається (кілька потоків пишуть враз одне й те саме), колекція ламається
(«Collection was modified»). Захист:
- `lock` — CPU-bound, синхронний код;
- `SemaphoreSlim` — async, IO-bound (SaveAsync, API);
- `Interlocked` (`Increment`, `Decrement`, `Exchange`, `CompareExchange`) —
  атомарні цілі;
- `Concurrent*` — колекції з внутрішню синхронізацію.
Правило: **одна колекція / один файл — один потік одночасно**;
інші чекають (await або lock wait).

## 12. LINQ Min / Max / Average

`Min`, `Max`, `Average` — агрегатні (aggregates) методи LINQ.
На числових колекціях вони повертають:
- `Min`: найменше значення;
- `Max`: найбільше значення;
- `Average`: середнє арифметичне.
У нашому Project (в Program.cs):
`songs.Min(x => x.DurationSeconds)`, `songs.Max(...)`,
`songs.Average(...)`. Використовуємо для
статистики: середня тривалість пісень, найдовша, найкоротша
пісня, середні оцінки.

## 13. LINQ Select

`Select` — проєкція (projection): перетворює кожний елемент
на нове значення. `songs.Select(x => x.Title)` повертає
колекцію назв (не пісень). Використовуємо, коли треба змінити
тип або витянути (select) один елемент з великого (наприклад,
`SelectMany` — витребувати (витянути) вкладені
колекції в одну). У Program.cs: `Select` для
найдовшої за тривалістю пісні.

## 14. LINQ Where

`Where` — фільтр (filtering): залишає елементи,
які виконують умова (умова/поріг).
`songs.Where(x => x.DurationSeconds > avg)` — пісні,
тривалість яких більша за середню.
У Program.cs: `Where` для
пісень із тривалістю > середньої.

## 15. LINQ Aggregate

`Aggregate` — агрегація (fold/згорнення): накопичувач
(aкумулятор) проходить колекцію, і кожен елемент
«згортається» в накопичувач. `songs.Aggregate(0.0,
(acc, x) => acc + x.DurationSeconds)` — сума всіх
тривалостей. Замінює звичайний for-цикл, який додає кожен
елемент в суму. Або: `Count` / `Sum` — спеціальні
агрегати для типізованих випадків.

## 16. LINQ OrderBy

`OrderBy` — сортування (sort): повертає колекцію
відсортовану (за індексом).
`OrderByDescending` — від найвеликшого
до найменшого. `songs.OrderByDescending(x => x.DurationSeconds)` —
найбільша (за тривалістю) спочатку.
`Take(3)` — перші 3 елементи (top 3).
Chain (ланцюжки методів): `OrderByDescending(...).Take(3)` —
топ-3 найдовших (за тривалістю).

## 17. LINQ vs цикли (for / foreach)

- **LINQ** — декларативний (declarative) стиль: «що» треба
  (фільтрувати, сортувати, агрегувати), а не «як».
- **цикли for/foreach** — імперативний (imperative)
  стиль: «крок за кроком».

На стандартному коді (`Where`/`Select`/`OrderBy`) різниця
у швидкості невелика (CLR оптимізує). LINQ читається
швидше, менше помилок, легше тестувати і рефакторити.
Цикли краще, коли потрібен нестандартний алгоритм:
`break` (зупинитися), `continue`, індекси, змінні
стану (state). У нашому Project: LINQ — для демонстрації
(агрегати, фільтри), цикли for/foreach — де треба
побудувати конкретні змінні (в паралелі, в
producer/consumer).

## 18. Одночасне збереження файла двома потоками (concurrent SaveAsync)

Проблема: два (або N) потоки одночасно викликають
`File.WriteAllText` (або `SaveAsync`) одним (однаковим)
файлом. Один пише «початок», інший — «кінчик»:
JSON ламається (corrupted), файл не валідний.
Рішення: **SemaphoreSlim на рівні 1** (статичний
`SemaphoreSlim _jsonWriteGate = new(1, 1)`):
- `await WaitAsync()` — «зайняти файл» перед записом;
- `await File.WriteAllTextAsync(filePath, json)` —
  асинхронний запис;
- `Release()` (у `finally`) — «віддати файл».
Виклик: `Task.WhenAll(save1, save2, save3, ...)` —
N конкурентних SaveAsync завершуються, і файл
залишається валідним (JSON). У нашому Project (в Program.cs,
block 5): 3 конкурентні SaveAsync, елементів у файлі
== елементів у сервісі, валідація JSON: true.

## 19. Parallel.For

`Parallel.For(from, to, body)` — паралельний цикл: тіло
виконується одночасно різними потоками пулу
(Thread Pool). На відміну від звичайного `for`,
процес може «зупинити» (обірвати) цикл на ранніх
ітераціях (за рахунок `ParallelLoopState.Break` або
`Stop`). Код після `Parallel.For` виконується **тільки
після** завершення ВСІХ ітерацій (join point — точка
зшивання). Не використовувати для IO (там async).
Використовувати для CPU-bound обчислень (в нас —
створення 2000 Song через `Random.Shared` і
`ConcurrentBag<Song>`). Результат: `ActualCount` (з
колекції, а не з коментаря), `Elapsed` (з Stopwatch) —
справжні (real) значення.

## 20. Пагінація (Pagination)

Пагінація (page-based) — сторінковий (page-based) доступ
для великих колекцій:
- `page` (номер сторінки, починається з 1);
- `amount` (кількість елементів на сторінці).
Через LINQ: `Skip((page - 1) * amount).Take(amount)`.
Чому `page - 1`? Бо нумерація (номерів) починається з 1,
а індекси — з 0: сторінка 2 з amount=20 = елементи
з індексами 20–39 (тобто 21–40 «зліва направо»).
Валідація:
- `page <= 0` або `amount <= 0` →
  `ArgumentOutOfRangeException`;
- сторінка поза межами колекції → **порожня
 колекція** (не помилка).
