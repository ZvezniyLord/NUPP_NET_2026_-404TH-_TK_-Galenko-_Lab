# Лабораторна робота №2 — Відповіді на контрольні запитання

Відповіді прив'язані до нашої реалізації (CrudServiceAsync<T>, Parallell, Program.cs, Unit-тести).

## 1. Що таке інтерфейс ICrudServiceAsync<T>? Яке його призначення? Чому доцільно використовувати generic тип T для CRUD-сервісу?

`ICrudServiceAsync<T> : IEnumerable<T>` — це асинхронний generic-контракт CRUD.
Його призначення: визначити метод (контракт) для створення, читання,
оновлення, видалення елементів колекції та асинхронного збереження
всіх у `Task<T>`, а також дозволити перебирання сервісу через `foreach`.

Generic тип `T` доцільний тому, що один і той самий сервіс можна
використовувати для різних типів об'єктів: `CrudServiceAsync<SoloSinger>`,
`CrudServiceAsync<Song>`, `CrudServiceAsync<VocalGroup>` тощо, не
дубуючи код. Обмеження `where T : IEntity` гарантує, що T має унікальний
`Id` (GUID) — це необхідна умова для пошуку/оновлення/видалення.

## 2. Що таке процес та потік, яка між ними різниця? Що таке багатопотокове виконання?

**Процес** — це програма, що виконується в пам'яті, з власним простором
адрес (пам'ять, дескриптори, реєстр). Це найвищий рівень ізоляції.

**Потік** (thread) — це потік виконання всередині процесу. Усі потоки
процесу мають один простір адрес, тому вони можуть спільно змінювати
спільні дані.

**Різниця:** процес ізольований, потік — частина процесу; потоки
закладено в одному процесі спільні дані.

**Багатопотокове виконання** — це одночасне виконання кількох
потоків. У .NET кожен потік виконується у ThreadPool (пул потоків).

## 3. Що таке асинхронність, яка різниця між асинхронністю та багатопотоковістю?

**Асинхронність** — це виконання операції, яка може бути затриманою
(I/O, мережа, заперечення), але потік виконавця не блокується:
потік "відказується" та повертається до іншої роботи, а результат
приходить пізніше через Task.

**Багатопотоковість** — це кілька потоків, які одночасно виконують
код (CPU-паралельність).

**Різниця:** асинхронність — це один потік, який "зупиняється" на
I/O (не блокує потік); багатопотоковість — кілька потоків, які
одночасно виконують код. Вони можуть поєднуватися.

## 4. Для чого використовуються ключові слова async/await?

- **async** — метод може використовувати `await` і повертає `Task`/`Task<T>`.
- **await** — асинхронне очікування завершення Task, без блокування потоку.

Приклади: `SaveAsync()` — асинхронний запис файлу;
`Task.Delay(100)` — асинхронне затримування (не блокує потік).

## 5. Чим відрізняється Task від ValueTask?

- **Task** — клас (об'єкт), який повертає результат або виняток.
  Створення Task — алігацийний alloc у пам'яті.
- **ValueTask** — struct (структура), яка повертає результат/виняток
  без алігации у пам'яті.

**Різниця:** Task — об'єкт (alloc у managed heap); ValueTask —
структура (без alloc), швидша в швидкості (наприклад, у гарячих шляхах).

## 6. Що таке thread-safe колекція? Які приклади таких колекцій у .NET?

**Thread-safe колекція** — колекція, до якої кілька потоків
одночасно можуть звертатися без ризику руйнування стану (race condition).

Приклади в .NET:
- `ConcurrentQueue<T>`, `ConcurrentDictionary<TKey, TValue>`, `ConcurrentBag<T>`
- `BlockingCollection<T>`
- `ArrayPool<T>` (пул масивів)

В нашій реалізації `CrudServiceAsync<T>` — `List<T>` сама не thread-safe,
тому ми використовуємо `lock (_syncRoot)` для захисту (критична секція).

## 7. Для чого використовуються примітиви синхронізації, такі як lock, Semaphore, AutoResetEvent?

**lock** — блокує доступ до одного ресурсу (критична секція).
Тільки один потік може увійти в lock-секцію.

**Semaphore (SemaphoreSlim)** — дозволяє обмежити кількість
одночасних операцій. `SemaphoreSlim(1, 1)` — "lock" але async;
`SemaphoreSlim(3)` — до 3 одночасно.

**AutoResetEvent** — подія "готово/не готово". Producer "кричить" `Set()`,
consumer "очікує" `WaitOne()`. Після WaitOne подія автоматично скидається.

## 8. Як забезпечити безпеку при одночасному зверненні кількох потоків до спільного ресурсу?

1. **lock** — критична секція: `lock (obj) { ... }`.
2. **Immutable** — незмінні дані (не модифікано).
3. **Lock-free** — атомарні операції (Atomic).
4. **Interlocked** — атомарні операції над змінними.
5. **Concurrent collections** — `ConcurrentQueue<T>` тощо.
6. **Semaphore** — обмеження кількості одночасних операцій.
7. **AutoResetEvent** — синхронізація producer/consumer.
8. **async/await** — асинхронне I/O (не блокує потік).

У нашій реалізації:
- `List<T>` захисний через `lock (_syncRoot)` (критична секція).
- File writing — захищений через `SemaphoreSlim(1, 1)`.
- `Random.Shared` — потокобезпечний Random.
- `lock` у `Parallell.LockDemo()` — демонстрація критичної секції.

## 9. Як за допомогою LINQ можна отримати мінімальне, максимальне та середнє значення певної властивості?

```csharp
int min = items.Min(s => s.Age);
int max = items.Max(s => s.Age);
double avg = items.Average(s => s.Age);
```

Приклад:
```csharp
IEnumerable<SoloSinger> singers = await service.ReadAllAsync();
int minAge = singers.Min(s => s.Age);
int maxAge = singers.Max(s => s.Age);
double avgAge = singers.Average(s => s.Age);
```

Лямбда `s => s.Age` означає: "для кожного елемента s взяти Age".

## 10. Чим відрізняються методи Select, Where, Aggregate, OrderBy?

- **Where** — фільтрація (тільки елементи, які задовольняють умову).
- **Select** — проєкція (вибір потрібного значення/типу).
- **Aggregate** — накопичувальна операція (сума, максимум, мінімум).
- **OrderBy** — сортування (за зростанням).
- **Min/Max/Average** — мінімум, максимум, середнє.

Приклад:
```csharp
var experienced = singers.Where(s => s.YearsOfExperience >= 10);
var names = singers.Select(s => s.StageName);
int totalExp = singers.Aggregate(0, (sum, s) => sum + s.YearsOfExperience);
var byAge = singers.OrderBy(s => s.Age);
```

## 11. Які переваги використання LINQ у порівнянні з класичними циклами?

- Короткість та читабельність.
- Ланцюгова обробка (composition): `.Where(...).Select(...).OrderBy(...)`.
- Делегатування оптимізації (Lazy evaluation).
- Менш коду = менш помилок.
- Легко переносити на інші колекції (IEnumerable<T>).

## 12. Що станеться, якщо два потоки одночасно спробують зберегти колекцію у файл?

**Без захисту:**
- Обидва потоки одночасно читають колекцію (snapshot).
- Обидва потоки одночасно пишуть у файл (File.WriteAllText).
- Один потік може перезаписати результат другого (last-write-wins).
- Файл може бути "коригованим" (частково записаний).

**З захистом (наша реалізація):**
- `Lock` — snapshot під lock (копія стану).
- `SemaphoreSlim(1, 1)` — одночасно в файл пише лише один потік.
- `finally` — звільнення semaphore навіть у разі винятку.

Результат: файл завжди містить останній "коректний" snapshot.

## 13. Як працює Parallel.For і у яких випадках його краще використовувати?

**Parallel.For(from, to, body)** — паралельно виконує body для
кожного i у діапазоні [from, to).

**Використовуємо, коли:**
- CPU-інтенсивні операції (алгоритми, розрахунки).
- Синхронні ітерації (не I/O).
- Короткі операції (не "довгі").

**НЕ використовувати:**
- async/await (I/O) — асинхронне очікування.
- Довгі операції (більше 10-20мс).
- Спільні дані без lock.

Приклад:
```csharp
Parallel.For(0, count, i =>
{
    T item = factory();
    service.CreateAsync(item).GetAwaiter().GetResult();
});
```

## 14. Що таке пагінація і як вона реалізована у нашій системі?

**Пагінація** — це поділ великої колекції на сторінки.

**Реалізація в CrudServiceAsync<T>:**
```csharp
public Task<IEnumerable<T>> ReadAllAsync(int page, int amount)
{
    if (page <= 0) throw new ArgumentOutOfRangeException(nameof(page));
    if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));

    List<T> snapshot = GetSnapshot(); // знімок (copy) під lock.

    // Skip = пропустити; Take = взяти.
    // page = 2, amount = 20 -> Skip(20).Take(20) -> елементи 21-40.
    var pageElements = snapshot.Skip((page - 1) * amount).Take(amount).ToList();
    return Task.FromResult(pageElements);
}
```

**Приклад:**
```csharp
var page1 = await service.ReadAllAsync(1, 10); // елементи 1-10.
var page2 = await service.ReadAllAsync(2, 10); // елементи 11-20.
```

**Валідація:** page <= 0 або amount <= 0 -> ArgumentOutOfRangeException.
**За межами:** порожня колекція (без винятку).
